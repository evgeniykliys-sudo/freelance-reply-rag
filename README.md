# freelance-reply-rag

RAG-автоматизация для фриланс-работы: вместо вопроса "какую услугу/цену/бриф
предложить под этот заказ" — бот ищет по смыслу в собственной базе услуг
(`FREELANCE.md`) и составляет черновик отклика строго на основе найденного,
без выдумывания цен и услуг, которых там нет.

Если заказ просит то, что в базе прямо помечено как отказ (обход защиты,
капча, многоаккаунтность) — бот не пишет продающий текст, а говорит отказать.
Если заказ не похож ни на одну услугу по смыслу — говорит, что он вне профиля,
а не притягивает что-то за уши.

## Откуда данные
Единственный источник — `C:\Projects\_docs\FREELANCE.md` (таблица услуг,
бриф-шаблоны, портфолио, шаблоны откликов). Копия контента никуда не
дублируется: изменил цену в FREELANCE.md — перезапустил `ingest.py` — бот
отвечает по новой цене.

## Запуск

```bash
python -m venv venv
venv\Scripts\pip install -r requirements.txt
copy .env.example .env
```

Заполни `.env`: `BOT_TOKEN`, `ANTHROPIC_API_KEY`.

```bash
python ingest.py   # строит векторный индекс из FREELANCE.md (нужно перезапускать при его изменении)
python bot.py
```

## Использование
Пришли боту текст заказа — в ответ придёт черновик отклика (или честное
"не подходит"/"не беру такое" вместо черновика) плюс отдельная пометка,
какая услуга и цена использованы — проверить перед отправкой заказчику.

## Тесты
`scripts/calibrate.py` — проверка сырых дистанций поиска на разных типах
заказов, использовался для подбора порога отсечения нерелевантных совпадений.
`scripts/test_draft.py` — полный прогон `draft_reply()`: обычное совпадение,
явный отказ, заказ не по профилю, пограничный случай (наём вместо разовой
задачи). Без assert — ручная проверка по выводу.
